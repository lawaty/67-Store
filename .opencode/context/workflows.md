# Workflows

- [binding] Dev: `npm run dev` (db up + next dev). DB: MariaDB via docker compose on 127.0.0.1:3307. — See `package.json`, `docker-compose.yml` (verified 2026-11-06)
- [binding] Order flow: storefront/checkout resolve VIP markup, price coins via coin index, place order → start/confirm payment → fulfil via distributor; refunds on fulfilment failure. Product availability against available USDT (recorded − reserved) gates live non-coin payments only — sandbox marks all buyable / skips the gate and coins bypass it; a live snapshot failure leaves products unbuyable (`unknown_balance`). — See `src/api/storefront.ts`, `src/api/checkout.ts`, `src/catalogue/application/product-availability.ts`, `src/container.ts` (verified 2026-11-07)
- [binding] Catalogue sync upserts products, appends cost history, deactivates missing, then updates coin index (`coin:index_*`) from cost changes via treasury coin indexer. — See `src/catalogue/application/sync-catalogue.ts`, `src/treasury/application/coin-indexer.ts`, `src/container.ts` (verified 2026-11-07)
- [binding] Treasury: funding records each lot with its total EGP paid (including fees) at record time, so it enters WAC immediately; deposits via `recordDeposit` guard reserved USDT against recorded USDT only — the live distributor balance never makes coins sellable; dashboards bridge recorded + free (حر / غير المسجل) to total g2bulk (live). The deposit rate plus coverage check lives in `createQuoteDeposit` (`deposit-quote.ts`), a non-writing quote shared by `recordDeposit` and wallet funding. — See `src/treasury/domain/funding.ts`, `src/treasury/application/service.ts`, `src/app/api/admin/funding/route.ts`, `src/treasury/application/record-deposit.ts`, `src/treasury/application/deposit-quote.ts`, `src/treasury/application/wallet-funding.ts`, `src/treasury/application/deposit-settings.ts`, `docs/01-domain/06-credits.md` §Pre-funding rule, `src/api/admin.ts`, `docs/03-specs/06-back-office.md` §Dashboard (`/management`) (verified 2026-11-07)
- [binding] Treasury funding cannot exceed free USDT: `recordFunding` reads the live distributor balance and the treasury snapshot and rejects with `exceeds_free` (nothing appended, fail-closed when either read throws) when `usdtMinor` exceeds `freeUsdtMinor(live, recorded)` (0 when live is null or below recorded); the funding modal caps the USDT input at free USDT and disables submit above it, and the server action maps the rejection to `?error=free`. — See `src/api/admin.ts`, `src/treasury/domain/wac.ts`, `src/app/api/admin/funding/route.ts`, `src/app/management/(shell)/treasury/funding-modal.tsx`, `src/app/management/(shell)/treasury/actions.ts`, `src/app/management/(shell)/treasury/page.tsx` (verified 2026-11-07)
- [binding] Funding rollback: `DELETE /api/admin/funding/[id]` (admin-guarded) calls `rollbackFunding` to remove the lot only when recorded USDT and EGP basis after removal stay non-negative and recorded stays at or above reserved coin backing; otherwise it returns `locked` (409) and removes nothing; the treasury server action maps errors to `?error=locked` / `?error=not_found`, and funding rows render `RollbackFundingButton` (confirm dialog) with the page rendering `?ok=rolledback` plus those errors. — See `src/app/api/admin/funding/[id]/route.ts`, `src/api/admin.ts`, `src/treasury/ports/funding-repository.ts`, `src/infrastructure/prisma/treasury-repository.ts`, `src/app/management/(shell)/treasury/actions.ts`, `src/app/management/(shell)/treasury/page.tsx`, `src/app/management/(shell)/treasury/rollback-funding-button.tsx` (verified 2026-11-07)
- [binding] Dashboard trend: the admin dashboard supplies a 90-day daily profit spine (delivered orders' margin), a cumulative WAC series (funding minus consumption per day), and P2P history; `DashboardTrend` and `TrendChart` share a selectable 7/14/30-day window slid by an offset (`windowDays`/`windowOffsetDays`), plotting one domain at a time (live-cost as 3-hour slots with min/average/max, WAC, or profit in daily/cumulative mode). — See `src/api/admin.ts`, `src/infrastructure/prisma/treasury-report-repository.ts`, `src/app/management/(shell)/trend-chart.tsx`, `src/app/management/(shell)/dashboard-trend.tsx`, `src/app/management/(shell)/trend-chart-geometry.ts`, `src/app/management/(shell)/page.tsx` (verified 2026-11-07)
- [binding] P2P rate read: the jobs `p2p` route calls `p2pRate.read()` (fresh Binance quote within the sync-interval TTL; on failure expired cache → manual → last-known → null, persisting last-known and appending hourly history on fresh reads; the cache is keyed by outlier sigma), while `readDashboard`/`readAdminStats` serve `readP2pLatestRate` (persisted last-known, stale past 2× the sync interval) first and fall back to `p2pRate.read()` only when no last-known exists (dashboard per-method rates null on the persisted path). The sync interval defaults to 300s (range 300–10,800s; a stored 300 is honored as 300), the aggregation window is 1–720h (default 24h), and the outlier sigma is 1–5 (default 2) — all editable via `POST /api/admin/settings/p2p` and carried into `history.p2p`/`DashboardDto.p2p.range`.
  — See `src/treasury/application/p2p-rate.ts`, `src/api/admin.ts`, `src/shared/p2p-settings.ts`, `src/treasury/application/p2p-rate-settings.ts`, `src/app/api/admin/settings/p2p/route.ts`, `docs/02-architecture/03-p2p-rate-integration.md` §Settings keys, `docs/02-architecture/05-deployment.md` §Scheduled jobs (verified 2026-11-08)
- [binding] Storefront preferred payment method: the visitor's choice is persisted in the `default_method` cookie (written by `CurrencySwitcher`, read server-side by `readPreferredMethod`); storefront pages use it and fall back to the store default method from settings exposed via `/api/storefront/method` (`readDefaultMethod`) when the cookie is absent or invalid. — See `src/app/(storefront)/preferred-method.ts`, `src/app/currency-switcher.tsx`, `src/app/api/storefront/method/route.ts`, `src/app/(storefront)/layout.tsx`, `src/api/storefront.ts` (verified 2026-11-07)
- [binding] Management sidebar stats: `SidebarStats` polls `GET /api/admin/stats` (`readAdminStats`) every 30s and on visibility return, window focus and route change, hides on 401, and dims on error after first success; the mobile bar layout (`chrome.tsx`) reuses the same cells. — See `src/app/management/sidebar-stats.tsx`, `src/app/management/sidebar-stats.test.tsx`, `src/app/management/chrome.tsx`, `src/app/api/admin/stats/route.ts`, `src/api/admin.ts` (verified 2026-11-07)
- [binding] Player verification: storefront player-id/zone fields verify as the visitor types via debounced `POST /api/players/verify` (public, read-only, never writes a profile or order), and block submit while checking, invalid, or unverified; `checkPlayer` in the API layer delegates to `distributor.checkPlayer` with a blank game defaulting to `mlbb`. — See `src/app/api/players/verify/route.ts`, `src/api/players.ts`, `src/api/contracts/player.ts`, `src/fulfilment/ports/distributor.ts`, `src/ordering/domain/player.ts`, `src/app/(storefront)/player-check.ts`, `src/app/(storefront)/player-identity-fields.tsx`, `src/app/(storefront)/mlbb/profile-fields.tsx`, `src/app/(storefront)/account/profiles/page.tsx` (verified 2026-11-07)
- [binding] Customer wallet funding: `GET /api/account/fund` quotes and `POST` starts `createStartWalletFunding` (stores a PENDING `WalletFunding` with the quoted coins and fake reference); fake payment confirm branches on `purpose: funding` into `settleWalletFunding`, which idempotently marks PENDING→PAID, appends the deposit from the stored quote, credits the wallet, and attaches it. The storefront UI at `/account/fund` is sandbox-only: `readAccount` sets `fundingAvailable` only in sandbox, the wallet tab links there only then, and the page 404s otherwise; its quote form reads the quote API and the `startFunding` server action posts to the start API. — See `src/app/api/account/fund/route.ts`, `src/api/wallet-funding.ts`, `src/treasury/application/wallet-funding.ts`, `src/api/payments.ts`, `src/container.ts`, `src/api/account.ts`, `src/app/(storefront)/account/page.tsx`, `src/app/(storefront)/account/fund/page.tsx`, `src/app/(storefront)/account/fund/actions.ts` (verified 2026-11-07)
- [binding] Scheduled jobs are secret-guarded `POST /api/jobs/{poll,sync,reconcile,p2p}` routes invoked by the external scheduler (503 when `JOBS_SECRET` is unset, 401 on `x-jobs-secret` mismatch via `timingSafeEqual`);
  `p2p` calls `p2pRate.read()` once — cadence is the P2P sync interval setting — and returns `{ok, fetchedAt, source, stale, egpPerUsdtMinor}` with nullable fields when no rate resolves. — See `src/app/api/jobs/p2p/route.ts`, `src/app/api/jobs/poll/route.ts`, `src/app/api/jobs/sync/route.ts`, `src/app/api/jobs/reconcile/route.ts`, `src/env.ts` (verified 2026-11-07)
- [binding] Operations-mode switch: the dashboard `OperationsModeControl` posts `saveOperationsMode` (server action) → `POST /api/admin/operations-mode` (admin-guarded) writes the mode setting; the dashboard DTO carries `operations {mode, liveReady}`, and `liveReady` is false while fake payment rails or an empty G2Bulk key would make live startPayment throw. — See `src/app/management/(shell)/operations-mode-control.tsx`, `src/app/management/(shell)/actions.ts`, `src/app/api/admin/operations-mode/route.ts`, `src/api/contracts/admin.ts`, `src/api/admin.ts`, `src/app/management/(shell)/page.tsx`, `src/container.ts` (verified 2026-11-07)
