# Architecture

- [binding] Next.js 15 + Prisma (MariaDB) monolith with strict TypeScript; DI via `src/container.ts` creating repositories/services. — See `package.json` (verified 2026-11-06)
- [binding] Domain is split into bounded contexts: `accounts/`, `backoffice/`, `catalogue/`, `ordering/`, `payments/`, `fulfilment/`, `treasury/`, `wallet/`, `promos/`, `alerts/`, `i18n/`. — See `src/container.ts`, `src/accounts/index.ts`, `src/backoffice/index.ts` (verified 2026-11-06)
- [binding] External reseller integration lives under `src/integration/g2bulk/` with anti-corruption via catalogue/fulfilment; P2P rate via `src/integration/binance-p2p/`. — See `src/container.ts` (verified 2026-11-06)
- [binding] Next.js App Router under `src/app/` with API routes in `src/app/api/`; presentation in `src/frontend/` and i18n in `src/i18n/`. — See `src/app/layout.tsx`, `src/app/api/` (verified 2026-11-06)
- [binding] `src/api/` is the application/API layer: per-area services, DTO contracts, and shared http/auth/container helpers consumed by `src/app/api/**/route.ts`. — See `src/api/admin.ts`, `src/api/container.ts`, `src/api/contracts/index.ts` (verified 2026-11-06)
- [binding] Back-office presentation primitives live in `src/app/management/(shell)/viz/` (partition, bridge, rate ladder, move, P2P strip, status chips) over the shared formatter in `src/frontend/format.ts`; the dashboard and treasury
  pages compose them, with dashboard settings edits living in `p2p-settings-modal.tsx` that posts via server actions in `actions.ts`. The trend chart is separate, in the shell root (`trend-chart.tsx`, `trend-chart-geometry.ts`;
  composed with performance/projections plus a link to the levels page by `dashboard-trend.tsx`), and the dashboard page composes it from `history.p2p`/`history.wac` plus the daily profit spine in `summary.series`. — See `docs/03-specs/06-back-office.md` §Dashboard (`/management`), `docs/03-specs/06-back-office.md` §Navigation, `src/frontend/format.ts`, `src/app/management/(shell)/trend-chart.tsx`, `src/app/management/(shell)/dashboard-trend.tsx`, `src/app/management/(shell)/actions.ts`, `src/app/management/(shell)/p2p-settings-modal.tsx`, `src/app/management/(shell)/page.tsx` (verified 2026-11-07)
- [binding] Management treasury writes have two entry points: customer coin deposits post to `/management/coins` (`coins/actions.ts` server action → `POST /api/admin/deposit` → `recordDeposit`; page in `coins/page.tsx` with `purchase-modal.tsx`, reading `TreasuryDashboardDto.deposits` from `/api/admin/treasury`) and treasury funding posts to `/management/treasury` (`recordFunding`); both pages read the same `TreasuryDashboardDto` from `/api/admin/treasury`. The treasury page merges G2Bulk funding credits and order-consumption debits into one newest-first operations log from that DTO. — See `docs/03-specs/06-back-office.md` §Customer coin deposits (`/management/coins`), `docs/03-specs/06-back-office.md` §Treasury operations (`/management/treasury`), `src/api/contracts/treasury.ts`, `src/api/admin.ts` (`readTreasuryDashboard`), `src/app/management/(shell)/coins/page.tsx`, `src/app/management/(shell)/coins/actions.ts`, `src/app/management/(shell)/coins/purchase-modal.tsx`, `src/app/management/(shell)/treasury/page.tsx` (verified 2026-11-07)
- [binding] `src/container.ts` resolves the operations mode once per call (persisted `operations:mode` setting over env `OPERATIONS_MODE`, default sandbox) and routes the distributor, catalogue source, payment providers and deposit coverage through it — sandbox uses the fake adapters, live uses the G2Bulk/real adapters; later wiring must call `container.operationsMode()` and not read settings directly. — See `src/container.ts`, `src/shared/operations-mode.ts`, `src/env.ts`, `src/fulfilment/application/fake-distributor.ts`, `src/integration/fake/catalogue-source.ts`, `src/payments/application/fake-provider.ts` (verified 2026-11-07)
- [binding] Storefront `/account` has four tabs (wallet, orders, profiles, levels); the levels tab renders `LevelsPanel` (current level, effective margin, progress to next, achievements wall incl. orphaned badges whose key left the curve) from `AccountDto.levels`, which `readAccount` computes for MLBB (qualifying volume → progress → effective markup, earned badges recorded lazily) alongside wallet/orders/profiles. — See `src/app/(storefront)/account/page.tsx`, `src/app/(storefront)/account/levels-panel.tsx`, `src/api/account.ts`, `src/api/contracts/account.ts`, `src/frontend/account.ts` (verified 2026-11-07)
- [binding] VIP level editing lives on `/management/levels` (`levels/page.tsx` reading `vipLevels` from settings, rendering `vip-curve-editor.tsx`); `saveVipCurve` in `actions.ts` posts to `POST /api/admin/settings/vip-curve` → `saveVipLevels`, and the dashboard `pricing-controls.tsx` only links
  to it (sidebar and mobile chrome link/title it too). — See `src/app/management/(shell)/levels/page.tsx`, `src/app/management/(shell)/vip-curve-editor.tsx`, `src/app/management/(shell)/actions.ts`, `src/app/management/(shell)/pricing-controls.tsx`, `src/app/management/sidebar.tsx`, `src/app/management/chrome.tsx`, `src/app/api/admin/settings/vip-curve/route.ts`, `src/api/admin.ts` (verified 2026-11-07)
